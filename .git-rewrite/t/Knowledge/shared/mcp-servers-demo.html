Architecture

One gateway, one guard, many domain modules

There is exactly one MCP endpoint for the whole platform. Every domain adds a module, not a new server — this is what keeps the surface a curated, ~5–15-tool-per-domain catalog instead of an unmanageable wall of one-tool-per-endpoint entries.

Security model

Three trust tiers, one enforcement point

Every tool call, regardless of module, passes through the same guard before it ever reaches domain logic. The tiers are additive in privilege, not interchangeable — the highest-risk tools are permanently out of reach of the two external-facing tiers, by design.

TierCarried asWhoReach
HumanOnly Authorization: Bearer <JWT> A real logged-in user with TenantAdmin/Admin role Only tier that can call create_credential, create_agent, create_mcp_server — permanently unreachable by the two tiers below
Scoped API key X-Api-Key: <key> An external caller — e.g. a Claude Custom Connector Any tool covered by the key's mcp:{module}:{read|write} scopes, strictly bound to that key's own tenant — no cross-tenant access, ever
Same-tenant agent X-Mcp-Agent-Id: <id> An in-product Octopus agent Regular tools within its own tenant only
Why this fits Claude specifically: Claude's remote-connector auth (the static_headers mode) sends one fixed credential as a request header on every call — and X-Api-Key is one of only two header names Claude pre-approves without any extra review. The scoped-API-key tier above is not a new thing built for Claude; it is the exact mechanism Claude already expects from any external MCP server.

The existing design document is stale, not just unbuilt. It assumes a standalone, separately-registered MCP server — superseded by the merged-gateway pattern Forms and Flows already prove out. Before any code is written this needs: (1) rehosting as a fourth module on the same gateway, (2) a new IAppStudioExtendedService for the two composite operations (create-project-then-app, create-widget-then-place), (3) server-side validation of widget configuration against each widget type's real schema, and (4) publish gated behind the HumanOnly tier rather than left out entirely.
Plan

Path to “all three, externally usable”

Ordered by risk and dependency — certify what exists before building what doesn't, and prove the external path before opening it to the internet.

Phase 1 · Certify what's already built

Prove Flows and the API-key tier actually work

  • Apply the Workflow module's seeded DB rows to a live environment
  • Live-verify tools/list and a full create/read/update/delete round trip for all 12 workflow tools
  • Open an MCP-created node in the real Flow Studio UI to confirm the connector-pairing invariant holds
  • Run the Credentials module's round trip and confirm no plaintext secret ever appears in a tool response
  • Run the scoped-API-key tier itself for the first time — the literal mechanism external Claude access depends on has never been exercised live
Phase 2 · Close known gaps

Fix what certification will surface

  • Fix the commented-out CreatedBy/LastModifiedBy stamping in the shared base repository
  • Remove the hardcoded TenantID = 1 fallback on the internal agent path
  • Wire rate limiting onto the MCP endpoint before any external traffic reaches it
Phase 3 · Build Apps

Bring App Studio to parity with Forms and Flows

  • Rewrite the design for the proven merged-gateway hosting model
  • Build BizFirst.Ai.Mcp.Tools.AppStudio and IAppStudioExtendedService
  • Add mcp:app-studio:read / mcp:app-studio:write scopes to the access catalog
  • Certify with the same read+write, real-data standard Forms already met
Phase 4 · Open it up

Make it reachable from a real Claude workspace

  • Expose /mcp on a public HTTPS domain
  • Each tenant provisions its own scoped API key via the existing admin key management
  • Tenant adds a Custom Connector in Claude, auth type static_headers, header X-Api-Key
  • Any conversation in that workspace can now build forms, workflows, and apps — strictly within that tenant, with agent/credential/server creation still locked to real logged-in admins
