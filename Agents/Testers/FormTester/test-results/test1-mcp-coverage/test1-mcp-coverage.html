BizFirst Atlas Forms · MCP Test 1

Full MCP Server Coverage — Atlas Forms

A real, end-to-end exercise of every Atlas Forms MCP tool: create a form, mutate it through every write operation, query it back through every read operation, and verify the result independently against the live database — not just the tool’s own success response.

Coverage summary

All 15 Atlas Forms MCP tools, one real form, one continuous session

Every call below is a real tools/call JSON-RPC request against the live server (http://localhost:5001/mcp), authenticated with a real scoped API key (mcp:atlas-forms:write). One test form (FormID 10001137) was created, mutated through every write tool, and independently verified against the real Atlas_Forms database row via SQL — not just trusting each tool's "success": true.

Findings from this run

Real gotchas, not just a pass/fail list

Dashboard caching gap (frontend, not MCP): after add_form_control/update_form_control/etc., reopening the same "View" modal on the Form Definitions list still showed the old data — the dashboard loads the form list once and doesn't invalidate it on modal reopen. A full page navigation (not just closing the modal) forces a fresh fetch. Worth knowing before assuming an MCP write "didn't work" when it's actually a stale UI.
Cross-checked against the database, not just the MCP response: after remove_form_control, SELECT (SELECT COUNT(*) FROM OPENJSON([Schema],'$.controls')) FROM Atlas_Forms WHERE FormID=10001137 returned 4 — matching exactly. The [Schema] column is legacy ntext, not nvarchar(max) — needs an explicit CAST before any JSON function will touch it.
